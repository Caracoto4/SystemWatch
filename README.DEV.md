# SystemWatch — внутренняя документация разработки

Этот файл — подробная рабочая память проекта. Пользовательский README находится в корне репозитория и должен оставаться коротким, наглядным и понятным конечным пользователям. Здесь фиксируются архитектура, технические решения, ограничения, команды, тесты и следующие задачи.

## 1. Цель и обязательные принципы

SystemWatch — portable-инструмент диагностики Windows с интерактивным TUI. Главный принцип: собирать проверяемые факты, объяснять их и не выдавать предположения за неисправности.

- По умолчанию только чтение.
- Не чинить систему автоматически.
- Не удалять/перемещать файлы, не менять реестр, службы, брандмауэр или настройки Defender.
- Не выполнять DISM/SFC с параметрами восстановления автоматически.
- Не объявлять процесс вирусом только по имени или высокой нагрузке.
- Недоступные проверки получают Unavailable, а не Healthy.
- Не экспортировать лишние персональные данные.
- Каждая диагностика должна сообщать источник данных, время, ограничения и результат.

## 7. Категории результата

- Critical — сильное подтверждение серьёзной неисправности.
- Warning — есть основание для внимания, но это не обязательно отказ.
- Info — контекст или рекомендация.
- Healthy — конкретная проверка завершилась и не нашла проблему в своей области.
- Unavailable — проверка не поддерживается, недоступна или неприменима.

Finding должен включать id, category, severity, title, summary, evidence, source, observed_at, limitations, recommendation. Факт и гипотеза должны быть разнесены.

## 8. Совместимость Windows

Не обещать Windows 7/8/8.1 до проверки target requirements зависимостей и тестирования. Текущий bootstrap использует современные версии Rust crates; минимальная ОС будет определена по результатам сборок и тестов. Не снижать версии зависимостей вслепую ради красивой таблицы совместимости.
